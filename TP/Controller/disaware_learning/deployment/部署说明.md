# ROV 实机部署说明

推荐严格按下面顺序部署：

```text
VIO -> NMPC -> latent JEPA-MPPI -> 六电机 mixer -> TCP -> ROV
```

NMPC 和 latent 共用 VIO、reference、六电机映射和 TCP 传输层。切换 controller 时不要同时修改这些边界。

## 1. 文件和模型

部署代码在：

```text
src/disaware_learning/disaware_learning/deployment/
```

| 文件 | 作用 |
|---|---|
| `controllers.py` | NMPC、latent 统一输出四轴 command |
| `protocol.py` | 四轴到六电机、PWM、24 字节协议帧 |
| `transport.py` | TCP、heartbeat、传感器分帧、neutral/disarm |
| `observation.py` | ROV 传感器 + 外部 VIO -> `VioState`/16D observation |
| `history.py` | latent 的 causal observation/action history |

latent checkpoint：

```text
src/disaware_learning/checkpoints/stage2_zhat_response_potential_full4096_four_modal_e5.pt
```

当前代码是部署组件，不是已经写死 VIO、reference 和主循环的一键程序。上层程序需要调用这些组件。

## 3. 先部署 VIO

协议传感器帧没有 XY 位置和线速度，这两项必须由 VIO 提供。VIO 输出必须是：

```text
position_ned_m                  [x,y,z]，m
orientation_body_to_ned_xyzw   [x,y,z,w]
linear_velocity_body_frd_m_s    [vx,vy,vz]，m/s
timestamp_seconds
```

坐标约定：世界 NED（+z 向下），机体 FRD（+x 前、+y 右、+z 下），四元数 `xyzw`，方向 body -> NED。

VIO 通过静止和低速移动检查后，和协议传感器合成 observation：

```python
import numpy as np

from disaware_learning.deployment import (
    ExternalRovObservationAdapter, ExternalVioPose, decode_sensor_frame,
)

sensor = decode_sensor_frame(raw_sensor_frame)
vio = ExternalVioPose(
    position_ned_m=position_ned_m,
    orientation_body_to_ned_xyzw=orientation_xyzw,
    linear_velocity_body_frd_m_s=body_velocity_m_s,
    timestamp_seconds=timestamp_seconds,
)
state, observation = ExternalRovObservationAdapter().observe(sensor, vio)
```

observation 必须是：

```text
rotation6D[6] + body_velocity[3] + gyro[3]
+ gravity_compensated_acceleration[3] + relative_depth[1] = 16D
```

协议 IMU 示例有歧义：`01 80 00 -> +180.00` 与 packed-BCD 规则不一致。必须保存真实原始帧校准 `RovSensorDecodeConfig`，确认前不要正式闭环。

## 4. 被动验证 TCP

ROV 是 TCP server：`192.168.1.7:8887`。

```python
from disaware_learning.deployment import RovTcpConfig, RovTcpTransport

transport = RovTcpTransport(RovTcpConfig())
transport.connect()
try:
    raw = transport.receive_sensor_frame(timeout_seconds=2.0)
    print(len(raw), raw.hex() if raw else "timeout")
finally:
    transport.close()
```

先只收传感器，不发送电机帧。确认帧为 32 字节、`AA ... FF`，周期约 100 ms，深度/姿态/电量合理，漏水为 0。

## 5. 六电机映射和 PWM

默认映射：

```text
m1 -> L1, m2 -> L2, m3 -> L3, m4 -> R1, m5 -> R2, m6 -> R3
L4/R4 -> 1500
```

四轴 mixer：

```text
m1 = yaw - surge + sway
m2 = -yaw - surge - sway
m3 = -yaw + surge + sway
m4 = yaw + surge - sway
m5 = -heave_up
m6 = -heave_up
```

`pack_command()` 将 normalized `[-1,1]` 转成协议 PWM `[1000,2000]` 并打包 24 字节帧。默认映射和方向必须通过实机确认；方向错误用 `SixMotorChannelMap(signs=...)` 修正，不改模型。

低功率顺序：

1. 不使能发送全 `1500`；
2. `arm=0` 确认设备收帧；
3. 单电机小偏置确认编号和正方向；
4. 确认 `L4/R4` 固定 `1500`；
5. 通过后才做 `arm=1` 小幅测试。

## 6. 先运行 NMPC

```python
from disaware_learning.deployment import NmpcDeploymentController

controller = NmpcDeploymentController()
controller.reset([0, 0, 0, 0])
```

NMPC 需要上层提供 `NmpcReference`，协议不包含轨迹目标：

```python
from disaware_learning.control.nominal_nmpc import NmpcReference

reference = NmpcReference.from_arrays(
    position_ned_m=reference_position_nodes,
    body_velocity_frd_m_s=reference_velocity_nodes,
    yaw_rad=reference_yaw_nodes,
    yaw_rate_rad_s=reference_yaw_rate_nodes,
    source="external_planner",
)
result = controller.update(state, reference, previous_command=last_command)
frame = pack_command(result.command, arm=0)
transport.send_motor_frame(frame)
last_command = result.command
```

NMPC 阶段只验证 VIO、reference 坐标/时间、command 方向、六电机映射和 heartbeat。先做小范围速度/深度保持，再做低速轨迹。

## 7. 再切换 latent JEPA-MPPI

```python
from disaware_learning.deployment import LatentDeploymentController

controller = LatentDeploymentController(
    "src/disaware_learning/checkpoints/"
    "stage2_zhat_response_potential_full4096_four_modal_e5.pt",
    device="cuda",
)
```

latent 需要 26 帧 16D observation、26 帧六电机 normalized action、当前 NED position、`ReferenceTrajectory` 和上一条四轴 command。

启动时用 neutral 填充 history：

```python
import numpy as np

from disaware_learning.deployment import (
    CausalHistoryBuffer,
    command_to_six_motor_normalized,
)
history = CausalHistoryBuffer(history_steps=controller.history_steps)
history.seed(np.zeros(16, dtype=np.float32), np.zeros(6, dtype=np.float32))
```

只有动作实际执行、下一帧 observation 到来后，才追加 transition：

```python
motors, raw = command_to_six_motor_normalized(last_command)
history.append_transition(next_observation, motors)
observations, actions = history.arrays()
```

调用：

```python
result = controller.update(
    observations,
    actions,
    reference,
    previous_command=last_command,
    current_position_ned_m=state.position_ned_m,
)
transport.send_motor_frame(pack_command(result.command, arm=0))
```

latent action history 是六电机 normalized action，不是 PWM、不是四轴 command。切换 latent 时不改变 VIO、reference、PWM、mixer 和 history 定义。

## 8. 推荐阶段

```text
0  被动 TCP + 原始帧记录
1  VIO 静止/移动验证
2  NMPC 不使能验证 command
3  NMPC 低功率短时闭环
4  NMPC 正常低速轨迹
5  latent 使用同一 VIO/reference/PWM/mixer
6  latent 与 NMPC 同轨迹对照
```

每阶段保存原始传感器帧、VIO state、16D observation、四轴 command、六电机 normalized command、最终 PWM 帧和 controller diagnostics。

## 9. 必须的安全规则

- 启动默认 `arm=0`，电机 `1500`；
- heartbeat 建议 1 秒，不能超过 5 秒；
- TCP/VIO/传感器超时立即 neutral/disarm；
- PWM 超过 `1000~2000` 拒绝发送；
- 不用积分 IMU 代替 XY VIO；
- 不把 data2 的电机正反状态当 action history；
- 六电机方向、IMU 编码和 reference 坐标未确认前，不正式闭环。

完成标准：VIO、TCP、IMU 编码、六电机映射、NMPC 短闭环、latent 26-step history 和断线停机全部通过。
